# INCONSISTENTのログ整形・バッファ追加の高速化（2026-10-20）

前版 `687cdef` のI/O高速化に続き、solver_events.csvの行生成とメモリ内の追加処理を調べました。
Double、収束条件・反復上限、材料則、SRM探索条件は変更していません。
計算DLLと材料DLLは前版の配布ファイルをそのままコピーしています。

ビルドは `20261020_INCO_EVENT_02`。
[実行ブックとDLL2個の一括ZIP](../workbook/SoilFEM_INCONSISTENT_EVENT_20261020.zip) を展開し、同じフォルダに置いてください。
保存済み解析結果は元ブックのものです。入力を確認して再解析してください。

## 調査と変更

調査用42手続きのQPC計測では、P6SolverEventは109,847回。
排他的な時間は共通列の生成など4.677秒、FEMIoCsvの置換が330,134回で0.970秒、
FEMIoAppendCsvが2.595秒でした。前版で残った費用は実ファイル書き込みだけではありません。

新しい `EVENT_LOG_FAST=1` は、ステージ番号・種別・丸め前Fs・増分番号が同じ間、整形済みの共通列を再利用します。
直前と同じイベント名も、CSV用に置換した文字列を再利用します。
詳細文字列は各行で処理し、カンマ・CR・LFを含む場合だけ従来と同じReplaceを行います。
Formatの桁数、列順、CRLF、ヘッダー、イベント件数・順序を維持します。
解析開始時にキャッシュを初期化します。実行中の地域設定変更は想定していません。
DEBUG_MODE=OFFの場合は行生成を省きますが、呼出し元で既に評価された詳細文字列の生成まで省くものではありません。

バッファは65,536文字以上の領域を確保し、Mid$で有効末尾へ行とCRLFを追加します。
容量が足りない場合だけ拡張し、書き込みはLeft$(バッファ, 有効長)で有効部分に限定します。
成功したフラッシュ後に有効長を0へ戻し、確保済み領域を再利用します。
失敗時は有効長・件数・内容を保持します。

バッファ単体のQPC比較（65,536行×3回の中央値、秒）は次のとおりです。
全探索の短縮率とは別の測定です。

|行の文字数|従来の連結|予約領域への追記|行配列＋Join|
|---|---:|---:|---:|
|128|0.170359|0.009983|0.013646|
|512|0.749556|0.024270|0.016621|

通常のイベント行に近い128文字では予約領域への追記が速く、これを採用しました。
いずれの方式も出力文字数を検査しています。長い行・容量拡張は別の実ファイル試験で確認します。

さらに、DLLから戻るGMRESイベント列は共通列とヘッダーを1回で準備し、
カーネル利用可否も1回だけ確認して各行を追加します。
各行のFullName確認・保存先変更の検出・512行のフラッシュ条件は従来の追加関数を通して維持します。
イベントコード1〜6の文字列と順序、コード3の前処理状態変更を維持し、状態は参照引数で元の求解側へ返します。
高速化無効・ログOFF・カーネル利用不可の場合は元の再生ループを使用します。


従来と同じ512行でフラッシュし、他のCSVの前・解析終了時にも書き込みます。
ロック時は保留内容を維持し、解除後に再試行します。
SaveAs、保留中の次回開始拒否、フォルダ再作成の挙動も維持します。
欠落時のEVENT_LOG_FASTは0です。配布ブックは1を保存し、開き直して確認します。
IO_FAST_PATH、NATIVE_STATE_COPY、NATIVE_GMRES_SIMDは比較の両側で1です。

最初の試作（共通列キャッシュとバッファ変更のみ）は、全探索3組の中央値が54.622秒→55.171秒で、全体の改善を確認できませんでした。
その時間を採用版の結果へ混ぜず、GMRESイベントの準備処理をまとめた02を改めて比較しています。
試作の生データもinitial_attemptに残しています。

## ログと境界条件の試験

実ExcelとWin32排他ロックを使用し、次を確認しました。

- 2,200回の変化するコンテキスト（ステージ・種別・Fs・増分・イベント名）と、空文字・日本語・カンマ・CR/LF・NUL・引用符。
- 512行の境界、70,000/140,000文字の行、長い行の後の短いフラッシュで予約末尾を出さないこと。
- ロック中に1,100行まで溜めた後の解除・追記・空フラッシュ。高速／従来で494,313バイト・3,282データ行とヘッダーが一致。
- native GMRESのコード1〜6・未知コード・ゼロ件・ログOFF・カーネル無効。入力配列の不変と、コード3の前処理状態の参照引数への反映。
- native replay経由でも、ロック中の1,100行と解除後の追記が従来経路とバイト一致。
- EVENT_LOG_FAST=0/1それぞれで、IO_FAST_PATH=0/1のロック・SaveAs・次回開始拒否・フォルダ再作成など24項目ずつ。

構築時は保存前と開き直し後に8モジュールをソース照合し、VBEコンパイルが通ったブックを使用します。

出力は引き続きベストエフォートです。途中Print失敗後の再試行で一部が重複する可能性や、
旧保留ログが書けない間の新出力先の行・直接CSVの見送りは[前版の制限](INCONSISTENT_IO_PERF.md#ログ再試行の試験と制限)を引き継ぎます。
ディスク満杯・電源断を含む無損失保証を追加したものではありません。

## 再現

[全変位を含む生JSON・QPC内訳・環境・ハッシュ](native-evidence/event_20261020/) を同梱します。
Excelを閉じ、VBAプロジェクトへのアクセスを信頼する設定を有効にし、PowerShell 7とPython 3を使用します。
既存の出力は上書きせず、新しい名前を指定してください。他のExcelがあると解析を開始しません。

```powershell
pwsh -NoProfile -File tests/native/build_event.ps1 -OutputDirectory tests/tmp/event_rebuild
pwsh -NoProfile -File tests/native/check_event_log.ps1 -Book tests/tmp/event_rebuild/2DSoilFEM_inco_event_20261020.xlsm -OutputDirectory tests/results/event_check_new
pwsh -NoProfile -File tests/native/check_io_fast.ps1 -Book tests/tmp/event_rebuild/2DSoilFEM_inco_event_20261020.xlsm -OutputDirectory tests/results/event_retry_new -EventFast 1
pwsh -NoProfile -File tests/native/run_inco_benchmark.ps1 -Book tests/tmp/event_rebuild/2DSoilFEM_inco_event_20261020.xlsm -OutputDirectory tests/results/event_pairs_new -EventOnly
python tests/native/summarize_io_benchmark.py tests/results/event_pairs_new --scope events --out tests/results/event_pairs_new/summary.json
python tests/native/test_io_summary.py
```

固定Fsは `run_native_compare.ps1 -Suite smoke -Modes AUTO -Flow INCONSISTENT -Precision AUTO -StateCopy 1 -GmresSimd 1 -IoFast 1 -EventFast 0/1`。
DAVISとの比較、`-Suite builtin -FixedFs 1`も同様に行います。
集計は `summarize_io_regression.py <基準JSON> <候補JSON> --scope events --out <集計JSON>`。
プロファイルは[前版の手順](INCONSISTENT_IO_PERF.md#再現)に従い、両側IoFast=1、EventFast=0/1を指定します。
