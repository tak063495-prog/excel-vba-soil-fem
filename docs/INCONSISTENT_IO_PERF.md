# INCONSISTENTのI/O高速化（2026-10-20）

ビルド `20261020_INCO_IO_01`。前版 `040c84c` の計算DLL・材料DLLをそのまま使い、
VBAのログ出力先の解決とフォルダ確認を減らします。
Double、収束許容値・反復上限、材料則、SRM探索条件、ログの通常時の内容と順序を維持します。

[一括ダウンロード](../workbook/SoilFEM_INCONSISTENT_IO_20261020.zip) を展開し、
XLSMとDLL2個を同じフォルダに置いてください。
ブックの保存済み解析結果は元ブックのものです。入力を確認して再解析してください。
前版のDLL高速化と今回のI/O高速化は別々の比較です。

## 変更

前版では `FEMIoOutDir` がsolverイベント1件ごとにブック名・保存先を組み立て、
フォルダの存在確認を繰り返していました。
今回の `IO_FAST_PATH=1` はブックのFullNameに対応する出力先を再利用し、
バッファに追加する段階でのフォルダ確認を、実際に書き出す段階へ移します。
通常の直接書き込みは従来どおりフォルダを確認します。
FullNameを毎回確認するため、SaveAsによる移動・改名を検出します。
未保存ブックではCurDirも識別に含め、クラウドURLでは従来の解決処理を使用します。
後者と未保存ブックは今回の動的試験の対象外です。

イベントは従来と同じ512行のバッファで追記し、他のCSV書き込み前・解析終了時にもフラッシュします。
失敗したフラッシュではパス・ヘッダー・保留バイトを残し、次回に再試行します。
保留中に保存先が変わっても、古いログは古い出力先へ書きます。
保留が解消しないまま次の解析を開始するとエラー `vbObjectError + 6210` を返し、実行間の混入を防ぎます。
ユーザー中断エラー18は再送出します。

配布ブックには `IO_FAST_PATH=1` を保存し、開き直して確認しています。
欠落時は0で、比較用に従来のパス解決・行ごとの確認経路を選択します。
このキーは追加設定として保持されます。計算精度の選択は従来どおりAUTO/SSE2/STRICTです。

この小モデルの改善率を大規模モデル・別CPU・別ストレージへ一般化しません。
大規模文献ケースの全探索は今回再実行していません。
Fs区間は数値的な収束境界の推定であり、物理破壊や設計安全率の確定値ではありません。

## ログ再試行の試験と制限

`check_io_fast.ps1` は実ExcelとWin32の排他ファイルハンドルを使用します。
0/1の両経路で、バッファ、フォルダ削除からの再作成、ロック中の保留、他CSVの先行防止、
保留中の次回開始拒否、ロック解除後の再試行、実SaveAs、旧出力先への保留分の書き込み、
新出力先のヘッダーと行順を確認しました。24項目が通過し、最終保留行数は0です。

以前の試験失敗は、テストの行頭の `FEMIoFlushEvents:` がVBAのラベルとして解釈され、
再試行を呼び出していなかったことが原因でした。`Call FEMIoFlushEvents` に修正しています。
最終試験は診断用の本体書き換えを外し、配布と同じ本体コードで行いました。

ログ出力はベストエフォートです。Open前のロック失敗からの再試行は確認しましたが、
ディスク障害などでPrintの途中まで書けた後に失敗する場合は、保留全体の再試行で一部行が重複する可能性があります。
トランザクションや厳密な一度だけの書き込みを保証する実装ではありません。
また、古い保留ログがロックされたまま出力先を変更すると、新出力先のその行は受け付けません。
保留をフラッシュできない間は直接CSVの追記も見送ります。全I/O障害で無損失という意味ではありません。
ロックを解除してから再実行してください。途中Print失敗・ディスク満杯・電源断は今回の障害試験の対象外です。

## 再現

[生データ・集計・環境・ソースのハッシュ](native-evidence/io_20261020/) を保存しています。
ブックを作るスクリプトはソースを埋め込み、保存前後で照合し、DLLを前版からそのままコピーします。
出力先が存在する場合は上書きしません。
Excelを閉じ、VBAプロジェクトへのアクセスを信頼する設定を有効にして、PowerShell 7とPython 3で実行します。
他のExcelがある場合、スクリプトは解析を開始しません。

```powershell
pwsh -NoProfile -File tests/native/build_io.ps1 -OutputDirectory tests/tmp/io_rebuild
pwsh -NoProfile -File tests/native/check_io_fast.ps1 -Book tests/tmp/io_rebuild/2DSoilFEM_inco_io_20261020.xlsm -OutputDirectory tests/results/io_check_new
pwsh -NoProfile -File tests/native/run_inco_benchmark.ps1 -Book tests/tmp/io_rebuild/2DSoilFEM_inco_io_20261020.xlsm -OutputDirectory tests/results/io_pairs_new -IoOnly
python tests/native/summarize_io_benchmark.py tests/results/io_pairs_new --out tests/results/io_pairs_new/summary.json
python tests/native/test_io_summary.py
```

固定Fsの比較は `run_native_compare.ps1 -Suite smoke -Modes AUTO -Flow INCONSISTENT -Precision AUTO -StateCopy 1 -GmresSimd 1 -IoFast 0/1` を使います。
FlowをDAVISにした比較と、`-Suite builtin -FixedFs 1` の比較も行います。
`summarize_io_regression.py <基準JSON> <候補JSON> --out <集計JSON>` は時間の揺れを許容し、数値と通常ログの完全一致を検査します。
プロファイルの作り方は[前版の説明](INCONSISTENT_NATIVE_PERF.md)と同じです。
今回は追加して `-StateCopy 1 -GmresSimd 1 -IoFast 0/1` を指定します。
