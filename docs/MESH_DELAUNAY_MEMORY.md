# デローニ分割の作業メモリー最適化

`Mesh.bas` の旧 `PINPUT` は、境界辺の間隔・細分化位置・細分化数を、節点番号を添字にした3つの密行列 `imno`（Double）、`deno`（Long）、`sms`（Long）で保持していました。これらは境界辺に現れる組合せだけが必要なのに、入力点数 `NOB + NIB` の二乗で確保されます。

今回の更新では、3表を `Scripting.Dictionary` に置き換え、キーを `元節点番号:元節点番号` としました。順方向・逆方向の辺を別キーで保持し、未登録の読み出しは従来のゼロとして扱います。共有辺が逆向きに現れる場合、同じ辺に異なる間隔が指定された場合は、従来どおり小さい間隔を採用します。境界の閉路と重複読み出しも独立Python検査で確認します。

これはメッシュ結果の節点番号、細分化数、材料則、Double精度、解析収束条件を変更するものではありません。Dictionaryの検索分だけPINPUTの辺処理が増える可能性があるため、CPU時間が必ず短くなる変更ではありません。目的は、入力点数が多い形状での二乗メモリー確保を避けることです。

密行列の理論値（配列ヘッダーとDictionaryオブジェクトの管理領域を除く）は次のとおりです。

| 入力点数 n | 旧3密行列の要素分メモリー | 新方式の保存量の目安 |
|---:|---:|---:|
| 200 | 約0.61 MiB | 辺数に比例 |
| 1,000 | 約15.3 MiB | 辺数に比例 |
| 1,800 | 約49.4 MiB | 辺数に比例 |

入力点数と、細分化後の生成節点数は別です。上表は入力点数についての `16×n²` バイトで、生成節点数を代入した値ではありません。他の基本作業配列約13MB、Variant、ワークシート、表示図形などは引き続き必要です。入力容量と既存の品質条件は維持しています。

## Excelでの実測・出力照合

最適化後の配布ブックをExcel 16.0 build 20430でコンパイルし、保存後再オープンして33モジュールをソース照合しました。専用コピーのPINPUTへ計測呼出しだけを挿入し、`GetProcessMemoryInfo` のPagefileUsage（プライベートなコミット量）を、3表の確保前と境界間隔表を保持している細分化開始直前で記録しました。

| 正多角形の入力点数 | 旧版の増加量 | 最適化後の増加量 | 減少量 |
|---:|---:|---:|---:|
| 200 | 0.606 MB | 0.057 MB | 0.549 MB |
| 1,000 | 16.601 MB | 0.639 MB | 15.962 MB |
| 1,800 | 52.765 MB | 1.077 MB | 51.687 MB |

MBは1,000,000バイトです。これは同じPCで旧版、新版を順次1回ずつ実行した、**境界処理の前後におけるExcelプロセス全体の増加量**です。ワークシート操作やメモリー管理の影響を含み、Excel全体の最大使用量、配列だけの厳密な使用量、全モデル共通の削減率を表すものではありません。Working Setも生ログへ保存しています。

正多角形3例は入力点数による確保量を調べるため、辺の細分化を発生させない条件です。加えて、隣接2領域が共有辺を逆方向に使い、格子間隔を1mと0.5mに指定した例を実行しました。全4例でPINPUTが返した全座標、元節点番号、細分化後の境界接続・閉路が旧版と完全一致しました。従来の方式0/1の生成メッシュ全セル・品質値も回帰試験で一致しています。

計測を含むPINPUT時間は1,800点で4.34→4.24秒、1,000点で1.33→1.39秒でした。単発値のため、計算時間の短縮率は主張しません。この正多角形試験はPINPUTまでの試験であり、多数点モデルのデローニ生成全体を検証したものでもありません。

```powershell
python tests/check_delaunay_memory.py
pwsh -File tests/run_delaunay_memory.ps1 -Book <旧版xlsm> -Out <旧版用の新規フォルダー>
pwsh -File tests/run_delaunay_memory.ps1 -Book <更新版xlsm> -Out <新版用の新規フォルダー>
python tests/check_delaunay_memory.py --compare <旧版フォルダー> <新版フォルダー> --report <照合結果.json>
```

Excelが起動済みの場合は計測を開始しません。記録ZIPの `delaunay_old/reference_memory_book.xlsm` が、この実測で使った最適化前のブックです。
